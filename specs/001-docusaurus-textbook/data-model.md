# Data Model: Docusaurus Physical AI Textbook Platform

**Feature**: `001-docusaurus-textbook`
**Date**: 2025-11-30
**Phase**: 1 (Design)

## Overview

This document defines the data structures, state management patterns, and entity relationships for the Docusaurus textbook frontend. Since this is a static site with external API integration, the data model focuses on client-side state and API contracts rather than database schemas.

---

## 1. Core Entities

### 1.1 Chapter

**Description**: A self-contained educational unit covering a specific topic (e.g., "ROS 2 Nodes and Topics").

**Structure**:
```typescript
interface Chapter {
  id: string;              // Unique identifier (e.g., "ch-ros2-nodes")
  path: string;            // URL path (e.g., "/docs/module-1/nodes")
  title: string;           // Display title (e.g., "ROS 2 Nodes and Topics")
  module: string;          // Parent module ID (e.g., "module-1-ros2")
  order: number;           // Sequence within module (e.g., 1, 2, 3)
  content: string;         // Markdown content (loaded by Docusaurus)
}
```

**Storage**: Markdown files in `frontend/docs/` directory
**Access Pattern**: Loaded at build time by Docusaurus; chapter ID mapping via plugin

**Relationships**:
- Belongs to one **Module**
- Referenced in **ChatbotQuery** for context
- Cited in **SourceCitation** for answers

---

### 1.2 Module

**Description**: A thematic grouping of related chapters (e.g., "Module 1: ROS 2 Fundamentals").

**Structure**:
```typescript
interface Module {
  id: string;              // Unique identifier (e.g., "module-1-ros2")
  title: string;           // Display title (e.g., "Module 1: ROS 2 Fundamentals")
  description: string;     // Brief overview
  order: number;           // Sequence in curriculum (1, 2, 3, 4)
  chapters: Chapter[];     // Child chapters
}
```

**Storage**: Defined in Docusaurus `sidebars.js` configuration
**Access Pattern**: Navigation sidebar structure

**Relationships**:
- Contains multiple **Chapters**
- Defines learning sequence

---

### 1.3 ChatbotQuery

**Description**: A user-submitted question with optional selected text context.

**Structure**:
```typescript
interface ChatbotQuery {
  query_text: string;         // User's question (max 1000 characters)
  chapter_id: string | null;  // Current chapter ID (e.g., "ch-ros2-nodes")
  user_id: string;            // User identifier (default: "guest-user")
  selected_text?: string;     // Optional highlighted text (max 500 characters)
}
```

**Validation Rules**:
- `query_text`: Required, non-empty, ≤ 1000 characters
- `chapter_id`: Must match existing chapter ID or be null
- `user_id`: Required, non-empty string
- `selected_text`: Optional, ≤ 500 characters if provided

**State Management**: Ephemeral (not persisted); sent directly to backend API

**Relationships**:
- References a **Chapter** (for context)
- Produces a **ChatbotResponse**

---

### 1.4 ChatbotResponse

**Description**: An answer generated by the RAG system with source citations and metadata.

**Structure**:
```typescript
interface ChatbotResponse {
  answer: string;                    // Generated answer text
  sources: SourceCitation[];         // Relevant textbook sections
  confidence_score: number;          // 0.0-1.0 (avg similarity of top 3 sources)
  grounding_status: GroundingStatus; // fully_grounded | partially_grounded | speculative
  processing_time_ms: number;        // Backend processing time
  metadata: {
    query_text: string;              // Original query (for history)
    chapter_id: string | null;       // Context chapter
    timestamp: string;               // ISO 8601 datetime
  };
}
```

**Derived Fields**:
- `grounding_status` calculated from `confidence_score`:
  - `fully_grounded`: confidence ≥ 0.7
  - `partially_grounded`: 0.3 ≤ confidence < 0.7
  - `speculative`: confidence < 0.3 (backend may return error instead)

**State Management**: Stored in React component state; displayed in chatbot widget

**Relationships**:
- Contains multiple **SourceCitations**
- Triggered by a **ChatbotQuery**

---

### 1.5 SourceCitation

**Description**: A reference to a specific textbook section used to generate an answer.

**Structure**:
```typescript
interface SourceCitation {
  chunk_id: string;          // Vector DB chunk identifier
  chapter_id: string;        // Chapter reference (e.g., "ch-ros2-nodes")
  section_title: string;     // Section heading (e.g., "Node Communication")
  content_excerpt: string;   // Text snippet (first 200 chars of chunk)
  similarity_score: number;  // 0.0-1.0 (cosine similarity to query)
  page_number?: number;      // Optional page reference (if applicable)
}
```

**Validation Rules**:
- `similarity_score`: Must be 0.0 ≤ score ≤ 1.0
- Sources sorted by `similarity_score` descending

**Display Pattern**:
```
Source: ROS 2 Nodes and Topics - Node Communication (similarity: 0.85)
"ROS 2 nodes are fundamental building blocks..."
```

**Relationships**:
- References a **Chapter**
- Included in **ChatbotResponse**

---

### 1.6 TextSelection

**Description**: User-highlighted text on the current page.

**Structure**:
```typescript
interface TextSelection {
  text: string;              // Selected text content
  range: DOMRect | null;     // Bounding box coordinates (for tooltip positioning)
  startOffset: number;       // Start character position
  endOffset: number;         // End character position
}
```

**State Management**: Ephemeral React state; cleared when selection changes

**Lifecycle**:
1. User highlights text → `mouseup` or `selectionchange` event
2. `window.getSelection()` captures text and range
3. Floating tooltip appears near selection
4. User clicks "Ask about this" → passes to **ChatbotQuery**
5. Selection cleared after query submitted

**Relationships**:
- Feeds into **ChatbotQuery.selected_text**

## 2. Client-Side State Management

### 2.1 Chatbot Widget State

**Component**: `src/components/ChatbotWidget.tsx`

**State Structure**:
```typescript
interface ChatbotWidgetState {
  isOpen: boolean;                       // Widget expanded or collapsed
  currentQuery: string;                  // User's input text
  conversationHistory: ConversationTurn[]; // Past Q&A pairs
  isLoading: boolean;                    // Waiting for API response
  error: string | null;                  // Error message (if request failed)
}

interface ConversationTurn {
  query: ChatbotQuery;
  response: ChatbotResponse;
  timestamp: string;
}
```

**State Transitions**:
1. **Initial**: `isOpen: false`, `conversationHistory: []`
2. **User opens widget**: `isOpen: true`
3. **User submits query**: `isLoading: true`, call backend API
4. **Response received**: `isLoading: false`, append to `conversationHistory`
5. **Error occurs**: `isLoading: false`, set `error` message

**Persistence**: None (state resets on page reload; conversation history ephemeral)

---

### 2.2 Text Selection State

**Component**: `src/components/SelectionTooltip.tsx`

**State Structure**:
```typescript
interface SelectionTooltipState {
  selection: TextSelection | null; // Current selection (null if none)
  isVisible: boolean;              // Tooltip shown or hidden
}
```

**State Transitions**:
1. **No selection**: `selection: null`, `isVisible: false`
2. **User highlights text**: `selection: {...}`, `isVisible: true`
3. **User clicks "Ask about this"**: Pass to chatbot, clear selection
4. **User clicks elsewhere**: Clear selection

## 3. API Contracts

### 3.1 Backend RAG Query Endpoint

**Endpoint**: `POST /v1/query`
**Base URL**: Configured via environment variable (`REACT_APP_API_URL`)

**Request Schema** (aligns with backend `QueryRequest`):
```typescript
{
  "query_text": "What are ROS 2 nodes?",
  "chapter_id": "ch-ros2-fundamentals",
  "user_id": "guest-user",
  "selected_text": "ROS 2 nodes are processes that perform computation"
}
```

**Response Schema** (aligns with backend `QueryResponse`):
```typescript
{
  "answer": "ROS 2 nodes are the fundamental building blocks...",
  "sources": [
    {
      "chunk_id": "chunk-001",
      "chapter_id": "ch-ros2-fundamentals",
      "section_title": "Node Basics",
      "content_excerpt": "ROS 2 nodes are processes...",
      "similarity_score": 0.85,
      "page_number": 12
    }
  ],
  "confidence_score": 0.72,
  "grounding_status": "fully_grounded",
  "processing_time_ms": 6826,
  "metadata": {
    "query_text": "What are ROS 2 nodes?",
    "chapter_id": "ch-ros2-fundamentals",
    "timestamp": "2025-11-30T14:23:45Z"
  }
}
```

**Error Response Schema** (aligns with backend `StandardErrorResponse`):
```typescript
{
  "error_code": "CONTEXT_NOT_FOUND",
  "message": "No relevant content found in the textbook to answer this question."
}
```

**HTTP Status Codes**:
- `200 OK`: Successful response with answer
- `400 Bad Request`: Invalid query format
- `401 Unauthorized`: Missing authentication (future feature)
- `404 Not Found`: No relevant context found
- `429 Too Many Requests`: Rate limit exceeded (future feature)
- `500 Internal Server Error`: Backend failure
- `503 Service Unavailable`: Backend unavailable

---

### 3.2 Backend Health Check Endpoint

**Endpoint**: `GET /health`

**Response Schema**:
```typescript
{
  "status": "healthy",
  "timestamp": "2025-11-30T14:23:45Z",
  "services": {
    "vector_db": "connected",
    "llm": "connected"
  }
}
```

**Usage**: Called on chatbot widget mount to check backend availability

## 5. State Lifecycle Diagrams

### Chatbot Query Lifecycle

```
[User types question]
    ↓
[User clicks Submit]
    ↓
[ChatbotWidget sets isLoading: true]
    ↓
[Call POST /v1/query with ChatbotQuery]
    ↓
[Backend processes RAG pipeline]
    ↓
    ├──[Success: 200 OK]
    │      ↓
    │  [Parse ChatbotResponse]
    │      ↓
    │  [Append to conversationHistory]
    │      ↓
    │  [Set isLoading: false]
    │      ↓
    │  [Display answer with sources]
    │
    └──[Error: 4xx/5xx]
           ↓
       [Set error message]
           ↓
       [Set isLoading: false]
           ↓
       [Display error to user]
```

### Text Selection Lifecycle

```
[User highlights text]
    ↓
[mouseup or selectionchange event fires]
    ↓
[window.getSelection() captures text + range]
    ↓
[SelectionTooltip sets selection state]
    ↓
[Tooltip appears near selection]
    ↓
[User clicks "Ask about this"]
    ↓
[ChatbotWidget opens with selected_text pre-filled]
    ↓
[Selection cleared]
```

## 8. Constraints and Invariants

### Data Integrity Constraints

1. **Chapter ID Uniqueness**: No two chapters can have the same `chapter_id`
2. **Module Order**: Module `order` values must be unique and sequential (1, 2, 3, 4)
3. **Chapter Order**: Within a module, chapter `order` values must be unique
4. **Similarity Score Range**: All `similarity_score` values must be 0.0 ≤ score ≤ 1.0
5. **Conversation History**: Must be ordered by `timestamp` ascending (oldest first)

### Business Rules

1. **Minimum Chapters**: Textbook must have ≥ 5 chapters to meet hackathon requirements
2. **Cognitive Load**: Each chapter should introduce ≤ 5 new technical concepts
3. **B1 Proficiency**: Content must be written at B1 English proficiency level
4. **Runnable Examples**: Each chapter must include ≥ 1 runnable code example

### Performance Constraints

1. **Query Timeout**: Chatbot queries must receive response within 10 seconds
2. **Page Load**: Chapter pages must render within 2 seconds
3. **Selection Response**: Tooltip must appear within 100ms of selection

This data model defines:
- **6 core entities**: Chapter, Module, ChatbotQuery, ChatbotResponse, SourceCitation, TextSelection
- **Client-side state patterns**: Chatbot widget, text selection, chapter context
- **API contracts**: Backend RAG query endpoint and health check
- **Validation rules**: Field constraints, business rules, performance requirements

All entities align with the backend RAG API schema to ensure seamless integration.
